# reflection 设计

读什么、为什么不做线索、session 笔记、产出、在哪跑。

## 读什么

主要读 Claude Code 和 Codex 的本地会话记录，PR 和 `TODO.md` 的变化作补充。只看 PR
看不到过程，而人在会话里纠正 agent 的地方最有价值。

会话记录很大，不能整篇交给模型。11/23 量过：过去 7 天 `~/.claude/projects/` 下有 308 个
session，共 362MB，中位数每个 675KB。拆开最大的一个：工具输出（文件内容、命令结果）约
200 万字符，工具调用约 22 万，人说的话加系统注入的文本约 6 万，agent 的回复不到 1 万。
有价值的部分只占 3% 左右。所以：

1. 先用脚本过滤：去掉工具输出，只留人说的话和 agent 的回复。这一步不用模型。
2. 过滤后的记录全部读一遍（全扫），分批交给几个 agent 并行读。

读记录、找教训这类量大的活用便宜的模型（比如 Sonnet），只有写提议时才考虑换更强的。
第一轮全扫一个月的个人记录：过滤后 1.8MB，6 个 Sonnet 并行，十几分钟（见
[记录](reflection-measure-20261123.md)）。

Claude Code 默认只留 30 天的会话记录（设置项 `cleanupPeriodDays`），新 session 启动后
在后台删掉更旧的；11/23 这台机器上最早的一份是 10/24，正好 30 天。所以反思至少 30 天
跑一次，否则有些记录还没读就没了。

读过的不再读：每个 workshop 记一个时间点，这之前的消息都算读过，下一轮只读之后的。按消息的
时间算，不按 session 算：一个 session 可能隔几天又接着用，接着用的那部分下一轮照样读。时间点
记在宿主上，不进 git，会话记录本来就只在这台机器上；具体放哪第 4 步定。一轮全部读完、PR 都
提了，才把时间点往后挪；中途失败，下一轮就重读。文件丢了就把 30 天内的全读一遍，多花一轮
全扫的钱（第一轮约 120 万 token）。没选的两种：按 session 记读到哪一条，要存的东西多，只有
一轮读到一半失败时才省事；什么都不记、每轮读最近 N 天，漏跑一次就漏掉一段。第一轮读到
11/24 00:32（北京时间）。

读哪些会话，由各 workshop 自己认领：它大概清楚哪些会话算自己的，反思只读认领的，读的
agent 能看到的也就是这些。怎么认领，第 4 步自动化时定；第一轮由 agent 挑了个人仓库的。
本机九成的记录属于个人仓库以外的项目，等它们的 workshop 来认领。容器里跑的
Codex 的记录退出后还在：contained-agent（uraj 里的 v1）把 `~/.codex/sessions/` 和
`~/.codex/archived_sessions/` 持久化到宿主，其余配置是临时的，退出就丢（11/23 查的）。

## 为什么不做线索

原来的设计：session 进行时就留下线索，标出“这里人纠正了 agent”“这件事值得写进
llm-wiki”，反思先读线索、再全扫兜底。线索不靠 agent 自觉记（Claude Code 的自动记忆靠
agent 自己判断，pylon 下几天里只记了 4 条），而是靠 hook：人发消息时用正则认出纠正，压缩前
提醒摘要保留还没记下的事；再加上已有的自动记忆。

第一轮全扫检验了它（见[记录](reflection-measure-20261123.md)）：

- 正则只抓到 13% 的纠正，抓到的里一半不是纠正；142 条教训里只有三成能被它指到。
- pylon 下的 4 条自动记忆，全扫也都找到了，没有多出东西。
- 全扫一个月的个人记录只要十几分钟，便宜到不需要线索来决定先看哪里。

所以 11/23 定了不做线索，每次全扫。

## session 笔记

每个 session 一份 session 笔记，只放待办（`todo.md`）：这个 session 里冒出来的事，觉得
“快做完了”时回来看一遍。hook 管三件事：开工时清掉旧笔记，压缩后把待办打出来，压缩前提醒
摘要保留还没写进去的待办。

为什么要它：待办现在放在 worktree 的 `tmp/`，压缩后要靠 agent 自己记得去读，worktree
删掉就没了。

放在哪：每个 session 一个目录 `~/.local/state/agents/sessions/<id>/`，在宿主上、所有
workshop 之外，容器挂进去。一个 session 常常跨好几个仓库，笔记不属于哪个 workshop。

不进 git：笔记是零碎的草稿，session 结束就没人再读，进 git 只会多出提交和冲突。

清理不用人做：开工的 hook 顺手删掉 30 天没动过的笔记目录。会话记录也只留 30 天（见
[读什么](#读什么)），30 天内恢复的 session 还找得到自己的待办。

hook 要拿到 session id 才能找到笔记，Claude Code 的 hook 输入里有。Codex 等
contained-agent-v2 再接，和 llm-wiki 的 hook 一样。

代码放在策略仓库里，做成全局 skill `session-notes`：`SKILL.md` 写 agent 怎么用笔记，hook
脚本放在它的 `scripts/` 下，和 llm-wiki 的索引脚本一样。skills 模块会把它装好，路径固定、
只跟 `main`；pylon 没有只跟 `main` 的检出，hook 找不到一个固定的脚本路径。hook 配置先由人
手动贴进 `~/.claude/settings.json`；要自动写，再交给 skills 模块，那会扩大它的影响范围，
到时再问人。

以后笔记也可能被当成 agent 之间传话的地方。那很像之前作废的信箱设计，到时要防止又做复杂。

## 产出

每条提议直接提 PR 到它所属的地方，在那个 PR 里和人商量；攒一批一起提。

- 外部知识：进对应 workshop 的 `llm-wiki/`，格式照 workshop skill。补上会话里查过、没写
  进去的；顺带把 `checked` 太旧的重新核对，索引里的 `!` 行修掉，重复的合并。
- 做事方式：看它该放哪：只关于一个 workshop 的，进那个 workshop（`AGENTS.md` 或项目
  skill）；所有 workshop 都适用的，向策略仓库提偏好或全局 skill 的改动。

每条都写明证据：哪个 session、人当时怎么说的。提炼出来的教训也可能是错的，出现次数多
不等于对；有出处，人审的时候才查得了，教训以后不适用了也知道当初为什么有它。引用人的
原话，不只写 session id：会话记录 30 天后就删了，原话还在。

对人的观察不单设文件（全局记忆），改写成要求，向策略仓库提偏好的改动。原来的设想是像
Hermes 那样，单独一个常驻文件记 agent 对人的了解，设硬上限。两种写法都进常驻上下文、都要
人批准；改写成要求（“PR 描述写短”而不是“人常在手机上看 PR”），agent 照着做就行，少一个
文件，人也只在一处审。策略仓库全局只有一个，工作机上也装，所以只写人怎么做事，不写任何
一方的隐私（见 [agent-policy 的决定](../261120-agent-policy/README.md#决定)）。第一轮里对
人的几条观察都能这样写（策略仓库 #12）。

## 在哪跑

在 contained-agent-v2 的容器里，由定时器启动。权限和挂载都复用 v2 的；直接在宿主上跑
agent 简单，但权限要另外收紧。代价是要等 v2。多久一次第 4 步再定，至少 30 天一次（见
[读什么](#读什么)）。在那之前，反思和 PR 里的讨论都是人开 session 让 agent 做。
