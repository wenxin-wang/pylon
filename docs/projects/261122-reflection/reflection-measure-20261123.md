# 第一轮全扫（11/23）

第 2 步的第一轮：读一个月的会话记录，看反思能找出什么，顺便检验抓纠正的正则。

## 范围

- 本机 Claude Code 的会话记录，10/24–11/23。更早的已经被 Claude Code 删了（30 天）。
- 只读个人仓库（pylon、uraj、khalis、spaces 等）的：147 个 session，人发的消息 710 条。
  按大小算，本机记录里九成属于其他项目，这一轮没读。
- Codex 的记录没读：跑这一轮的容器没挂 `~/.codex`。

## 做法

1. 过滤（`exp/reflection_20261123/filter_transcripts.py`）：121MB 剩 1.8MB。去掉的是
   工具调用和输出、思考过程、工具注入的文本（system reminder、Paseo 交接时附带的旧对话
   摘要、压缩摘要）。fork 出来的 session 会重复之前的对话，只留第一份。
2. 正则在读之前定好，命中的消息另存一份清单，不标在记录里，读的 agent 看不到。
3. 按时间分 6 批，每批交给一个 Sonnet agent 读全文。它要列出两样：人纠正 agent 的每一处；
   值得留下的教训，每条附人的原话。6 个并行，合计约 120 万 token，最慢的一个跑了 12 分钟。
4. Opus 合并教训：用脚本核对引用的原话，和已有的规则对照，写成 PR。

## 结果

- 纠正 230 处，占人发的消息的 32%。读的 agent 把“为什么这样做”这类追问也算进去了。
- 教训 142 条，各批之间有重复。按类分：做事方式 75 条，只关于某个仓库的 22 条，外部知识
  42 条，其他 3 条。按仓库分：所有仓库都适用的 72 条，uraj 52 条，pylon 12 条，其余 6 条。
- 提成 PR 的：策略仓库两个，偏好一个（#12），workshop skill 一句（#13）。证据和原话写在
  那两个 PR 里。
- 还没提的：
  - 外部知识 42 条，还没写进 llm-wiki，第 2 步接着做。
  - 只关于 uraj 的规则：uraj 要退役，等模块迁到 pylon 时一起带过来。
  - “被权限检查拦下就重试一次”：和工具自己的规则（被拦下要换做法，不要原样重试）冲突。

## 正则检验

| | 数量 |
|---|---|
| 正则命中的消息 | 66 条（710 条里的 9%） |
| 召回：230 处纠正里命中的 | 31 处（13%） |
| 准确：66 条命中里真是纠正的 | 31 条（47%） |
| 教训：至少有一条证据被正则命中的 | 142 条里 42 条（30%） |

Claude Code 的自动记忆也是线索的一个来源。pylon 下的 4 条，这一轮全扫都找到了，没有
多出来的东西。

结论：正则漏掉了大部分纠正；全扫一个月的个人记录只要十几分钟。11/23 人定了不做线索，
见[设计](reflection-design.md#为什么不做线索)。
